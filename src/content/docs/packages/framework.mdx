## What it does

The framework is the **backend**: the part of your app that runs on a server and handles data. One model definition drives everything:

- **Models:** describe your data once with `defineModel()` and `field.*` ([Models and fields](../../concepts/models-and-fields/))
- **Migrations:** database changes written for you, and never a guess about renames ([Migrations](../../concepts/migrations/))
- **The automatic API:** list, show, create, update, delete and restore for every model, with filters, search, sorting and pages ([The automatic API](../../concepts/auto-api/))
- **OpenAPI** at `/openapi.json` and a **resource manifest** at `/.well-known/strutvane.json`, which [`@strutvane/ui`](../ui/) reads to draw screens
- **Tenancy, twice:** every query is limited to the current tenant, and PostgreSQL row-level security backs it up ([Multi-tenancy](../../concepts/multi-tenancy/))
- **File storage and uploads:** `local` and `memory` disks, signed temporary links, and upload checks that look at the file's real content
- **Testing helpers:** `createTestApp()`, `actingAs()`, factories and a fresh database for every test

## When you need it

Whenever your app stores its own data. It's the heart of the **Full-stack** and **API only** presets.

## Install

```bash
npm install @strutvane/framework @strutvane/core
npm install @libsql/client   # SQLite. Or: pg (PostgreSQL), @electric-sql/pglite (in-process Postgres)
```

## Example: two models and a working API

```ts title="app/main.ts"
import { createApp } from '@strutvane/core'
import { createHttpApp, defineModel, field, frameworkProvider } from '@strutvane/framework'

export const Customer = defineModel('Customer', {
  name: field.string(120).searchable().sortable(),
  email: field.email().unique(),
  invoices: field.hasMany('Invoice'),
}, { tenant: true })

export const Invoice = defineModel('Invoice', {
  number: field.string(32).unique().searchable().sortable(),
  amount: field.decimal(12, 2).min(0).sortable().filterable(),
  status: field.enum(['draft', 'sent', 'paid']).default('draft').filterable(),
  customer: field.belongsTo('Customer').filterable(),
  notes: field.text().optional(),
}, { tenant: true, softDeletes: true })

const app = createApp({
  config: {},
  providers: [
    frameworkProvider({ database: { driver: 'sqlite', url: 'file:dev.db' }, models: [Customer, Invoice] }),
  ],
})
await app.boot()

// GET/POST /api/v1/invoices, GET/PATCH/DELETE /api/v1/invoices/:id, POST …/:id/restore,
// POST /api/v1/invoices/query, /openapi.json, /.well-known/strutvane.json, /health, /ready
export const http = createHttpApp(app, { resources: [Customer, Invoice] })
```

`http.fetch` runs on any server that speaks `Request`/`Response`: `@hono/node-server`, Bun, Deno or a serverless platform.

## Example: your own endpoint

Need something that isn't create, read, update or delete? Add a **custom route**. It gets the same permission checks and error format as the automatic ones:

```ts title="app/http/routes/api.ts"
import { route } from '@strutvane/framework/http'

export default [
  route.get('/hello', { public: true, handler: () => ({ message: 'Hello' }) }),
  route.post('/reports/revenue', {
    permission: 'report.revenue',
    handler: async ({ json, tenantId }) => reports.revenue(tenantId, await json()),
  }),
]
```

With `permission`, the [permission provider](../auth/) must allow the call. With `public: true`, anyone may call it. With neither, the caller must be signed in.

## Example: a test

```ts title="tests/feature/customer.test.ts"
import { createTestApp } from '@strutvane/framework/testing'

const t = await createTestApp({ resources: [Customer, Invoice] })
const alice = t.actingAs({ id: 'u1', type: 'user', roles: [], attrs: {} }, { tenantId })

const res = await alice.resource(Customer).create({ name: 'Acme', email: 'billing@acme.test' })
expect(res.status).toBe(201)
```

<Aside type="tip" title="Locked by default">
Without a permission provider (normally [`@strutvane/auth`](../auth/)), `createHttpApp` **refuses to start**, unless `APP_ENV=local` (everything is allowed, with a warning) or you set `publicApi: true` on purpose. You can't ship an open API by accident.
</Aside>

## Key options

| Option | Where | What it does |
|---|---|---|
| `database` | `frameworkProvider()` | `{ driver: 'postgres', url }`, `{ driver: 'sqlite', url }` or `{ driver: 'pglite' }`, or an existing connection |
| `storage` | `frameworkProvider()` | Your file storage disks and which one is the default |
| `models` | `frameworkProvider()` | The models your app uses |
| `resources` | `createHttpApp()` | Models (or `defineResource()` configs) to expose over HTTP |
| `basePath` | `createHttpApp()` | Where the API lives (default `/api/v1`) |
| `routes` | `createHttpApp()` | Your custom routes |
| `publicApi` | `createHttpApp()` | Explicitly run without a permission provider |
| `openapi` | `createHttpApp()` | Serve `/openapi.json` (on by default) |

## Databases

| Database | Status |
|---|---|
| PostgreSQL (including Neon, Supabase, AWS RDS and Azure with a password) | Supported, with row-level security. The recommended choice. |
| PGlite (Postgres running inside Node.js) | Supported; great for tests |
| SQLite (libSQL) | Supported; great for trying things out and for tests |
| MySQL 8.4 | Planned. `driver: 'mysql'` is accepted but throws `NotImplementedError` for now. |
| Azure passwordless sign-in for Postgres (Entra ID) | Planned |
| Microsoft SQL Server / Azure SQL | Planned after version 1.0 |

## Planned, not available yet

These are part of the design but not built yet: **background jobs, cache and email**; the interactive `/docs` page; custom actions on resources; filters through relations (`customer.name`); sparse fieldsets, bulk changes and export; ETags, rate limiting and request timeouts.
