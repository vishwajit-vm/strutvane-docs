## What it does

The CLI (command-line interface) is the tool you type commands into. Inside a project you run it as **`pnpm sv <command>`**. It generates models, policies and tests, checks your setup, adds packages and upgrades Strutvane without losing your edits.

There are two packages, released together:

| Package | What it is |
|---|---|
| `strutvane` | A tiny launcher with no dependencies. Inside a project, it hands every command to the project's own `@strutvane/cli`, so generated code always matches the versions in your `package.json`. |
| `@strutvane/cli` | The CLI itself: commands, generators, the registry compiler, installers and upgrades. Each project has it as a dev dependency. |

## Install

New projects already have both (`create-strutvane` adds them, plus the script `"sv": "strutvane"`). To add them to an existing project:

```bash
pnpm add -D strutvane@next @strutvane/cli@next
```

<Aside type="note">
On npm as a pre-release: `0.1.0-next.0` under the `next` tag. Install with `@next` (the `latest` tag still points at an empty name placeholder until 1.0).
</Aside>

## Example: your first commands

```bash
pnpm sv make:model Invoice number:string:unique "amount:decimal(12,2):min(0)" "customer:belongsTo(Customer)"
pnpm sv routes
pnpm sv doctor
```

1. `make:model` writes the model, a deny-by-default policy, a factory, a seeder and a feature test.
2. `routes` lists every endpoint with the permission it needs.
3. `doctor` checks Node.js, your `.env` files, `.gitignore` and more, and tells you how to fix each problem.

Outside a project, the launcher offers `strutvane new <name>` (which runs `create-strutvane`), `strutvane doctor --global`, `--version` and `help`.

## Flags that work on every command

`--json`, `--dry-run`, `--diff`, `--yes`, `--no-interactive`, `--force`, `--cwd <path>`, `--env <name>`, `--verbose`, `--quiet` and `--no-color`.

`sv make model` works the same as `sv make:model`, and unique prefixes work too: `sv mi:st` runs `migrate:status`.

The full list of commands, with examples, is on the [CLI commands](../../reference/cli/) page.

## Example: your own command

Any dependency named `@strutvane/*`, `strutvane-plugin-*` or `@scope/strutvane-plugin-*` can add commands. Point to them from its `package.json`:

```json title="package.json"
{ "strutvane": { "commands": "./dist/commands.js", "compat": "^0.1.0" } }
```

```ts title="src/commands.ts"
import { defineCommand } from '@strutvane/cli'

export default defineCommand({
  name: 'reports:send',
  description: 'Send monthly reports',
  args: { month: { required: true } },
  flags: { 'dry-run-email': { type: 'boolean' } },
  run({ args, out }) {
    out.success(`Sent reports for ${args.month}`)
    return { data: { month: args.month } }
  },
})
```

<Aside type="tip" title="Safe plugins">
A plugin's command file must live inside its own package folder, or it's refused without running. A plugin can never replace a built-in command, and a plugin whose `compat` range doesn't match your CLI is refused (exit code `7`).
</Aside>
