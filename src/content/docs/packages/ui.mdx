## What it does

Your Strutvane API publishes a **manifest**: a machine-readable description of every resource, its fields and what the current user may do (`GET /.well-known/strutvane.json`). The UI reads it and draws:

- **A list page** (`<ResourceList>`): columns, search, filter chips, sorting and pages. All the searching, filtering and sorting run **on the server**, and the list state lives in the URL, so you can bookmark or share it.
- **A create/edit form** (`<ResourceForm>`): the right input for each field type, validation as you type, and server errors shown next to the right field.
- **Buttons that follow permissions:** New, Edit and Delete only appear when the manifest says this user may use them.

The UI only talks to the backend over HTTP. It never imports the framework or auth packages, so it works with any API that publishes a Strutvane manifest.

## When you need it

When you want a web interface. It's part of the **Full-stack** and **UI only** presets.

## Install

```bash
npm install @strutvane/ui@next react react-dom @tanstack/react-query @tanstack/react-table @tanstack/react-form @tanstack/react-virtual
```

On npm as a pre-release: `0.1.0-next.0` under the `next` tag. Install with `@next` (the `latest` tag still points at an empty name placeholder until 1.0). React 19 and the TanStack packages are only needed for `@strutvane/ui/react`. The React-free core lives in `@strutvane/ui/core`.
</Aside>

## Example: a list and a form

```tsx title="web/app.tsx"
import { createHttpClient, fetchManifest } from '@strutvane/ui/core'
import { ResourceForm, ResourceList, StrutvaneProvider } from '@strutvane/ui/react'
import { QueryClient } from '@tanstack/react-query'

const api = createHttpClient({ baseUrl: 'https://api.example.com/api/v1', credentials: 'include' })
const manifest = await fetchManifest({ baseUrl: 'https://api.example.com', credentials: 'include' })
const invoices = manifest.resources.find((r) => r.name === 'Invoice')!
const queryClient = new QueryClient()

export function App() {
  return (
    <StrutvaneProvider api={api} manifest={manifest} queryClient={queryClient}>
      <ResourceList
        resource={invoices}
        initialSearch={location.search}
        onSearchStringChange={(s) => history.replaceState(null, '', s ? `?${s}` : location.pathname)}
        onCreate={() => navigate('/invoices/new')}
        onEdit={(row) => navigate(`/invoices/${row.id}/edit`)}
        confirmDelete={(row) => confirm(`Delete ${row.number}?`)}
      />
    </StrutvaneProvider>
  )
}

// /invoices/new  →  <ResourceForm resource={invoices} onSaved={(r) => navigate(`/invoices/${r.id}`)} />
// /invoices/:id  →  <ResourceForm resource={invoices} recordId={id} onSaved={…} onCancel={…} />
```

## Key props

| Component | Prop | What it does |
|---|---|---|
| `<StrutvaneProvider>` | `api`, `manifest`, `queryClient` | The HTTP client, the manifest and the React Query client |
| | `overrides` | Your own cells, widgets and message texts (see below) |
| `<ResourceList>` | `resource` | Which resource to list |
| | `initialSearch`, `onSearchStringChange` | Keep filters, sorting and paging in the URL |
| | `onCreate`, `onEdit`, `confirmDelete` | What New, Edit and Delete do |
| `<ResourceForm>` | `resource`, `recordId` | Create a record, or edit the one with this id |
| | `onSaved`, `onCancel` | What happens after saving or cancelling |

## Example: change one column and one input

Override any **cell** (how a value looks in the list) or **widget** (the input in a form) through the provider. Everything else stays automatic:

```tsx
import type { Cell, Widget } from '@strutvane/ui/react'

const Money: Cell = ({ value, record }) => <>{formatMoney(value, record.currency)}</>

const MoneyInput: Widget = ({ id, value, onChange, onBlur, describedBy, invalid }) => (
  <input id={id} value={String(value ?? '')} aria-describedby={describedBy} aria-invalid={invalid}
         onChange={(e) => onChange(e.target.value)} onBlur={onBlur} />
)

<StrutvaneProvider
  api={api}
  manifest={manifest}
  overrides={{
    fieldCells: { 'Invoice.amount': Money },              // one column of one resource
    widgets: { money: MoneyInput },                       // every field using this widget
    messages: { required: '{attribute} is mandatory.' },  // any message or UI text
  }}
/>
```

## Built in, so you don't have to

- **Accessible:** labels, help text and error messages are wired to every input (including yours). Tables have captions and sort states. Tests run axe-core on lists, forms and error states. WCAG 2.2 AA is a release requirement.
- **Friendly errors:** a `422` puts each problem next to its field (even `lines[1].amount`), or in a banner. Other errors (`403`, `409`, offline, server errors) show a friendly message, and what you typed is always kept.
- **Safe retries:** every save sends an `Idempotency-Key`, so pressing Save twice never creates two records.
- **Big lists stay fast:** rows are virtualised above 100, and the related-record picker searches the server and loads 100 at a time.
