## What it does

The devkit is the engine behind three CLI commands:

| Command | Devkit API | What it promises |
|---|---|---|
| `sv add <package>` / `sv remove` | `defineInstaller`, `runInstaller` | All or nothing, previewable, safe to run twice, reversible |
| `sv make:*` | `defineGenerator`, `runGenerator` | Typed, validated inputs; no template language, no `eval` |
| `sv upgrade` | `planUpgrade`, `applyUpgrade` | Your edits to generated files are never silently lost |

## When you need it

When you write a **plugin** or a package that sets itself up with `sv add`, or your own generators. If you only build apps, the CLI uses it for you.

## Example: an installer

An **installer** sets a package up in a project: config files, `.env` and `.env.example`, `package.json` and `strutvane.config.ts`. Every change is staged first, and written to disk together at the end (or not at all):

```ts title="src/installer.ts"
import { defineInstaller } from '@strutvane/devkit'

export default defineInstaller({
  name: 'notify',
  async install({ fs, env, deps, config, has, log }) {
    await fs.write('config/notify.ts', "export default { channel: 'mail' }\n")
    await env.add('Notifications', [
      { key: 'NOTIFY_DEFAULT_CHANNEL', value: 'mail' },
      { key: 'NOTIFY_SIGNING_SECRET', secret: true, comment: 'Signs webhook payloads' },
    ])
    await deps.add({ '@strutvane/notify': '0.1.0' })
    await config.registerProvider('@strutvane/notify/provider')
    if (!has('@strutvane/ui')) log.info('install @strutvane/ui for the notification centre')
  },
  async uninstall({ fs, env, deps, config }) {
    await fs.remove('config/notify.ts')
    await env.remove(['NOTIFY_DEFAULT_CHANNEL', 'NOTIFY_SIGNING_SECRET'])
    await deps.remove(['@strutvane/notify'])
    await config.unregisterProvider('@strutvane/notify/provider')
  },
})
```

Preview it, run it, undo it, and prove it's safe to run twice:

```ts
import { checkIdempotent, runInstaller } from '@strutvane/devkit'

const preview = await runInstaller(installer, { projectRoot, dryRun: true })
console.log(preview.diff)                                        // a diff; nothing written
await runInstaller(installer, { projectRoot })                   // write it
await runInstaller(installer, { projectRoot, mode: 'uninstall' }) // undo it
await checkIdempotent(installer, { projectRoot })                // [] when a second run changes nothing
```

What the helpers promise:

- **`fs`** never replaces a different existing file unless you pass `{ overwrite: true }`.
- **`env`** never overwrites an existing key. `secret: true` generates a random value for `.env` only, and **`.env.example` never receives a secret**.
- **`deps`** never replaces a dependency the project already has.
- **`config`** only edits the `providers` list in `strutvane.config.ts` and leaves everything else alone.

## Example: a generator

```ts
import { defineGenerator, runGenerator } from '@strutvane/devkit'
import { z } from 'zod'

const model = defineGenerator({
  name: 'model',
  inputs: z.object({ name: z.string().regex(/^[A-Z]\w*$/), fields: z.array(z.string()).default([]) }),
  files: ({ name, fields }) => [
    { path: `app/models/${name.toLowerCase()}.model.ts`, content: renderModel(name, fields) },
  ],
})

await runGenerator(model, { name: 'Invoice' }, { projectRoot, dryRun: true })
```

Templates are plain TypeScript functions, so there's no template syntax that could run code. Bad input throws a `GeneratorInputError` that lists every problem.

## Safe upgrades

When you change a generated file, the devkit keeps a copy of the original. On `sv upgrade` it does a **three-way merge**, like Git: original template, new template and your edited file. Clean changes are applied, conflicts are marked so you can resolve them, and a file you deleted is never recreated.
