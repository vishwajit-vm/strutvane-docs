## What it does

A **log** is your app's diary: "invoice sent", "payment failed", "request took 2 seconds". When something goes wrong, the log is where you find out why.

`@strutvane/logs` writes that diary for you, with no setup:

- **Zero configuration.** `log.info('Invoice sent', { invoiceId })` just works.
- **It never slows down or crashes your app.** Log calls are cheap and never throw. Writing to disk happens in the background, in batches.
- **Secrets never reach the disk.** Passwords, tokens, cookies, API keys, card numbers and similar values are replaced with `[REDACTED]` before anything is written.
- **Tidy storage.** One file per day in `storage/logs/`, a size cap per file, and old files cleaned up after 60 days.
- **Request logging.** One short line per request: method, route, status and how long it took. Query strings and request bodies are never logged.
- **A built-in viewer** at `/_strutvane/logs`, with search, filters, a live tail and downloads.

It works in **any Node.js 24+ app** (plain `node:http`, Express, Hono, or anything that speaks `Request`/`Response`), and new Strutvane projects get it **by default**.

## Example: your first log lines

```ts
import { log } from '@strutvane/logs'

log.info('Invoice sent', { invoiceId: 'inv_42', amount: 120 })
log.error('Payment failed', { orderId: 123, err: error }) // keeps the error's stack and cause

const billing = log.child({ module: 'billing' }) // every line from here includes module: 'billing'
billing.warn('Retrying charge', { attempt: 2 })
```

Each call becomes one JSON line in `storage/logs/2026-11-14.ndjson` (one file per day, in UTC):

```json
{"time":"2026-11-14T10:00:00.000Z","level":"info","msg":"Invoice sent","requestId":"9f1c…","fields":{"invoiceId":"inv_42","amount":120}}
```

The `requestId` was added automatically, because the line was logged during a request. **Levels**, from quietest to loudest: `trace`, `debug`, `info` (the default), `warn`, `error` and `fatal`.

## Add request logging and the viewer

Pick your server. `logs()` adds request logging **and** the viewer in one line:

<Tabs>
  <TabItem label="Hono">

```ts
import { Hono } from 'hono'
import { logs } from '@strutvane/logs/hono'

const app = new Hono()
app.use(logs())
```

  </TabItem>
  <TabItem label="Express">

```ts
import express from 'express'
import { errorLogging, logs } from '@strutvane/logs/express'

const app = express()
app.use(logs())
// … your routes …
app.use(errorLogging()) // logs unhandled errors with their stack, then passes them on
```

  </TabItem>
  <TabItem label="Any fetch server">

```ts
import { createRequestLogger } from '@strutvane/logs/http'

const requests = createRequestLogger()
export default { fetch: (request: Request) => requests.handle(request, (r) => app.fetch(r)) }
```

  </TabItem>
</Tabs>

Plain `node:http` servers use `withRequestLogging` and `toNodeHandler` from `@strutvane/logs/node`, plus `createViewerHandler` from `@strutvane/logs/viewer`.

Every request then logs one line like `GET /invoices/:id 200`. Server errors log as `error`, requests slower than one second as `warn`, and the `/health` and `/ready` checks are skipped.

## Who can open the viewer?

The viewer is **closed by default**, like a locked filing cabinet:

| Situation | Access |
|---|---|
| `APP_ENV=local` | Open, so `pnpm dev` just works |
| `LOGS_VIEWER_TOKEN` is set (16+ characters) | Send `Authorization: Bearer <token>`, or open `/_strutvane/logs?token=<token>` once in a browser. That sets an 8-hour cookie and removes the token from the address bar. |
| You pass an `authorize` callback | Your rule decides, for example "admins only" |
| Anything else (production with nothing set, say) | **404**, as if the viewer didn't exist |

```ts
logs({
  viewer: {
    authorize: async (request) => (await getUser(request))?.role === 'admin',
    ipAllowList: ['10.0.0.0/8'],              // optional: only these networks
    scopeRecords: (request) => {               // optional: each tenant sees only its own lines
      const tenant = tenantOf(request)
      return tenant ? (record) => record.tenantId === tenant : undefined
    },
    onAudit: (event) => auditLog.write(event), // record who cleared or downloaded logs
  },
})
```

## Settings

Everything works without settings. If you want to change something, use an environment variable or an option. Options win over variables, and variables win over the defaults.

| Variable | Default | What it does |
|---|---|---|
| `LOGS_ENABLED` | `true` | `false` turns every log call into a no-op |
| `LOG_LEVEL` | `info` | The quietest level that gets written |
| `LOG_FORMAT` | `pretty` locally, `json` elsewhere | The console format (files are always JSON) |
| `LOGS_DRIVER` | `file` | `file` or `stdout` |
| `LOGS_PATH` | `storage/logs` | Where the files go |
| `LOGS_RETENTION_DAYS` | `60` | Days to keep files (`0` keeps them forever) |
| `LOGS_MAX_DAILY_SIZE` | `30MB` | Size cap per file. A full file continues in `…-1.ndjson`. |
| `LOGS_VIEWER_TOKEN` | (none) | Opens the viewer for anyone with this token |

A wrong **environment value** never crashes your app: the default is used and one warning is logged. A wrong **option** in code throws straight away, because that's a programming mistake.

```ts title="Every option, in one place"
import { createLogger } from '@strutvane/logs'

const log = createLogger({
  level: 'debug',
  path: 'var/log/app',
  retentionDays: 14,
  sanitize: { extraKeys: ['iban'], extraPatterns: [/EMP-\d{6}/g] }, // redact these too
  bindings: { service: 'billing-api' },                             // added to every line
  handleShutdown: true,                                              // flush before the process exits
})
```

<Aside type="note" title="Planned">
A `database` driver, which stores logs in your database, is planned. Until then, `LOGS_DRIVER=database` falls back to `file` with a warning.
</Aside>
