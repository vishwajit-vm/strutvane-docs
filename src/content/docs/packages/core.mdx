## What it does

Core is the **engine room**. Every other Strutvane package plugs into it, and it depends on nothing except [`@strutvane/contracts`](../contracts/). There's no database, web server or UI inside, just the pieces everything else shares:

| Piece | In plain words |
|---|---|
| **Container** (`token`, `createContainer`) | A labelled shelf of services. Ask for "the mailer" and get the same one everywhere. |
| **Application** (`createApp`, `defineProvider`) | Starts packages in order (register, then boot) and shuts them down cleanly, with a timeout. |
| **Config** (`app.config('app.name')`) | Read-only settings. A wrong path is a type error, not a surprise at runtime. |
| **Env** (`defineEnv(schema)`) | Checks your [environment variables](../../concepts/environment-variables/) at start-up and lists **every** problem at once, without printing values. |
| **Request context** (`runWithContext`, `currentContext`) | Remembers the request id, user, tenant and language while a request runs. |
| **Hooks** (`createHooks`) | "Run my code before or after this happens." |
| **Events** (`createEventBus`) | "This happened" messages, like `invoice.sent`. One broken listener never affects the others. |
| **Errors** (`ValidationError`, `NotFoundError`, `DomainError`, `toProblem`) | One error shape for every API, with no internal details leaked. |
| **Messages** (`createMessages`, `defineMessages`) | Translatable message catalogs, with `{param}` and plural support. |
| **Logger** (`createLogger`) | A tiny fallback logger. [`@strutvane/logs`](../logs/) replaces it by default. |
| **Clock and ids** (`systemClock`, `uuidv7`) | The current time and time-ordered ids, both easy to fake in tests. |

## When you need it

Almost never directly: it comes with every other package. You'll use it yourself when you write your own **provider** (a plug-in that adds a service to your app) or want typed config and env checks in a plain Node.js app.

```bash
npm install @strutvane/core@next
```

## Example: a provider that sends a welcome email

A **provider** adds services to the container in `register`, then wires them up in `boot`:

```ts title="app/providers/mail.provider.ts"
import { z } from 'zod'
import { createApp, defineEnv, defineProvider, EventBusToken, LoggerToken, token } from '@strutvane/core'

interface Mailer {
  send(to: string, subject: string): Promise<void>
}
const MailerToken = token<Mailer>('mailer')

// Stops start-up with a clear message if MAIL_FROM is missing or not an email.
const env = defineEnv(z.object({ MAIL_FROM: z.email() }))

const mail = defineProvider({
  name: 'mail',
  register(app) {
    app.container.singleton(MailerToken, () => new SmtpMailer(env.MAIL_FROM))
  },
  boot(app) {
    app.make(EventBusToken).on('user.registered', async (event) => {
      const { email } = event.payload as { email: string }
      await app.make(MailerToken).send(email, 'Welcome!')
    })
  },
})

const app = createApp({ config: { app: { name: 'acme' } }, providers: [mail] })
await app.boot()
app.make(LoggerToken).info('Booted', { app: app.config('app.name') })

process.on('SIGTERM', () => void app.shutdown({ timeoutMs: 10_000 }))
```

## Example: friendly error messages

Errors carry a stable **code**. The words come from a message catalog, so you can change or translate them without touching code:

```ts
import { createMessages, defineMessages, DomainError, toProblem, ValidationError } from '@strutvane/core'

const messages = createMessages({
  app: [
    defineMessages('en', {
      'errors.INVOICE_ALREADY_PAID.title': 'Invoice already paid',
      'errors.INVOICE_ALREADY_PAID.detail': 'Invoice {number} was paid on {date}.',
    }),
  ],
})

toProblem(new DomainError('INVOICE_ALREADY_PAID', { number: 'INV-7', date: '2026-11-01' }), { messages })
// → { status: 422, code: 'INVOICE_ALREADY_PAID', title: 'Invoice already paid',
//     detail: 'Invoice INV-7 was paid on 2026-11-01.', … }

toProblem(new ValidationError([{ path: ['dueDate'], code: 'required' }]), { messages })
// → a 422 with issues: [{ path: ['dueDate'], code: 'required', message: '…' }]
//   and fieldErrors: { dueDate: ['…'] }
```

Plurals use the standard ICU format: `'{count, plural, =0 {No files} one {# file} other {# files}}'`.

<Aside type="tip" title="Safe by default">
An unexpected error (a bug, a crashed database driver) always becomes a plain `500` with **no internal details**. The full story goes to your logs, never to the person using your app.
</Aside>
