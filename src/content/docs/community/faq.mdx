## Is it free?

**Yes.** Strutvane is open source under the MIT license. That includes the "enterprise" features, such as roles and permissions, audit logs, multi-tenancy and single sign-on. Many other tools charge extra for those. We've written down that they will stay free.

## Can I use it today?

**Not yet.** Strutvane is in its design and foundations phase. The first version you can try (0.1) is planned for Phase 1. See the [roadmap](../roadmap/).

## Is it production-ready?

**No, not yet.** Version 1.0, after an independent security audit, is the "ready for production" milestone. Please don't build critical systems on early versions.

## Do I need to know TypeScript?

A little. If you can read this, you can follow along:

```ts
field.string().required()
```

Strutvane's errors explain what went wrong and how to fix it, and your editor helps by catching mistakes as you type.

## How is it different from Laravel?

Laravel is a fantastic PHP framework, and a big inspiration. Strutvane brings a similar experience (one command, conventions, first-party packages) to **TypeScript**. It also generates the **UI** and includes **roles, multi-tenancy and audit logs** out of the box.

## How is it different from NestJS or AdonisJS?

Those are excellent **backend** frameworks. Strutvane covers backend **and** frontend, and generates CRUD APIs, permissions and screens from your models. NestJS users will be able to use Strutvane's auth inside a NestJS app.

## How is it different from Payload, Strapi or Directus?

Those run a ready-made admin "engine" that you configure. Strutvane gives you **your own code**: you can read, change or replace any part of it. They're great tools; Strutvane is for teams who want full control and ownership.

## How is it different from Refine or React Admin?

Those are **frontend** toolkits. Strutvane's UI is similar in spirit, but it's backed by a matching backend that tells it about permissions, relations and validation. Its permission checks happen on the server too, not just in the browser.

## Which databases are supported?

PostgreSQL (recommended, including Azure, Neon, Supabase and AWS), MySQL and SQLite. Microsoft SQL Server is planned after 1.0. See [@strutvane/framework](../../packages/framework/).

## Will I get locked in?

No. Everything Strutvane generates is ordinary TypeScript in your project, and it's MIT-licensed. Even if Strutvane disappeared tomorrow, your app would keep working, and you'd own every line.

## Is Docker required?

No. Docker is optional and only used on your own machine to run a database easily. Without it, you can use SQLite.

## Where do I ask questions or report problems?

On [GitHub](https://github.com/vishwajit-vm/strutvane). Report security problems privately through the repository's **Security** tab, never in public issues.
