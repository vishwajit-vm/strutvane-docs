## Where we are now

<Badge text="Phase 1: Core, CLI and framework, in progress" variant="caution" size="large" />

**Phase 0 (foundations) is complete.** The blueprint is public, package names are reserved on npm, every package has its own repository, shared tooling and checks run on Linux, Windows and macOS, and nine experiments ("spikes", 419 tests) proved the riskiest ideas before any real code.

**Phase 1 is in progress.** Here's what's built so far. Every package below is implemented and tested at version `0.1.0-next.0`, but **not yet on npm**:

- ✅ [`@strutvane/contracts`](../../packages/contracts/): the shared definitions, including errors with `issues`, logging and file storage
- ✅ [`@strutvane/core`](../../packages/core/): container, providers, config, validated env, errors, translatable messages, events and hooks
- ✅ [`@strutvane/logs`](../../packages/logs/): zero-config logging with redaction, daily files, request logging and the built-in viewer
- ✅ [`@strutvane/framework`](../../packages/framework/): models, safe migrations, the automatic API with OpenAPI, tenancy with row-level security, file storage and testing helpers
- ✅ [`@strutvane/auth`](../../packages/auth/): policies that compile to SQL, tenant resolvers and row-level security, the Better Auth adapter and audit records
- ✅ [`@strutvane/ui`](../../packages/ui/): list pages and forms drawn from the manifest, with filters, validation, accessibility and overrides
- ✅ [`strutvane` and `@strutvane/cli`](../../packages/cli/): the commands, generators, registry compiler, `sv add` and safe upgrades
- ✅ [`@strutvane/devkit`](../../packages/devkit/): installers, generators and three-way merges
- ✅ [`create-strutvane`](../../packages/create-strutvane/): the project starter with `full`, `api` and `ui` presets

**What's next:**

- 🔨 **Publishing** the `0.1.0-next` pre-releases to npm
- 🔨 **Integration**: wiring the packages together end to end, so `npm create strutvane` gives you a running app
- 🔨 **The files package** (`@strutvane/files`): uploads, image handling and storage drivers on top of the framework's storage core
- 🔨 **Deferred items**, in later phases: background jobs, cache and email; MySQL and Azure passwordless databases; single sign-on, SCIM and two-factor sign-in; the `sv add auth` / `sv add ui` installers and the auth CLI commands; detail pages, sign-in screens and themes

<Aside type="note">
Timings assume a small core team and may change. Each phase only ends when its quality checks pass. We'd rather be late than broken.
</Aside>

## The phases

<Steps>

1. **Phase 0: Foundations** (weeks 0–4) · **complete**

   Names reserved, repositories, shared tooling and automated checks, and experiments ("spikes") for the hardest problems: turning models into migrations, turning permission rules into database queries, and database-level tenant isolation.

2. **Phase 1: Core, CLI and framework → version 0.1** (months 1–3) · **in progress**

   You'll be able to create a project, write models, run migrations, and get a working, documented API. **This is the first version you can try.** The packages are built and tested; publishing and integration are next.

3. **Phase 2: Auth → version 0.2** (months 3–5)

   Sign-in, roles, permissions, policies, multi-tenancy and the audit log. The authorization, tenancy and identity core is already built; this phase adds the sign-in API, the installer and the auth commands.

4. **Phase 3: UI → version 0.3** (months 5–7)

   Automatic screens, sign-in pages and theming. Full-stack apps in one command. The renderer core (lists, forms, filters) is already built; this phase adds routing, layouts, detail pages, sign-in screens and themes.

5. **Phase 4: Enterprise features → version 0.9 beta** (months 7–9)

   MySQL and Azure databases, single sign-on, background jobs, caching, monitoring and API versioning.

6. **Phase 5: Hardening → version 1.0** (months 9–12)

   An independent security audit, complete docs and example apps, and a long-term support promise. **Ready for production.**

7. **Phase 6: More packages** (year 2)

   Notifications, file uploads, payments and billing, reports, analytics, search and real-time updates.

</Steps>
