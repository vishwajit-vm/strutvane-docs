## The golden rules

1. **Write for a smart beginner.** Assume the reader is clever, but new to this topic.
2. **Use "you".** "You run `pnpm sv migrate`", not "the user runs".
3. **Short sentences.** One idea per sentence. Most paragraphs are 1–3 sentences long.
4. **An example everywhere.** Every concept gets a code sample, a table row, or a concrete scenario.
5. **Explain jargon on first use**, or link to the [glossary](../../reference/glossary/).
6. **Analogies help.** A keycard for permissions, an apartment building for tenancy, a car for levels of control.
7. **Be honest about status.** A feature that is built but not released yet gets a "Pre-release (0.1.0-next): APIs may still change" caution. Anything not built yet is clearly marked "Planned".
8. **Never contradict the blueprint.** The [blueprint](https://github.com/vishwajit-vm/strutvane/tree/main/docs) is the source of truth. If you spot a conflict, raise an issue.

## Before and after

**Before** (too dense):

> The resource engine compiles ModelDefinitions into handlers that apply policy-derived QueryFilter ASTs prior to persistence.

**After** (our style):

> When someone asks for a list of invoices, Strutvane first checks what they're allowed to see. Then it asks the database for only those invoices. You don't write that check yourself: it comes from your permission rules.

## Formatting rules

| Use | For |
|---|---|
| Tables | Comparisons, options, lists of commands |
| Code blocks with a `title=` | Any file the reader creates or edits |
| `<Steps>` | Instructions done in order |
| `<Aside type="tip">` | Helpful extras |
| `<Aside type="caution">` | "Pre-release" and "Planned" notices, and gotchas |
| `<Aside type="danger">` | Anything that can lose data or leak secrets |

## Links

Always use **relative links** between pages, such as `../models-and-fields/`. They keep working when the site moves to a new address. The build checks every link and fails if one is broken.

<Aside type="tip">
Read your page out loud. If you run out of breath in a sentence, split it.
</Aside>
