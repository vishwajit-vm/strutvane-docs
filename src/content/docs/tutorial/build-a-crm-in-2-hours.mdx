## What we're building

A small **CRM** (Customer Relationship Management) app for a sales team:

- **Companies:** the businesses you sell to
- **Contacts:** people who work at those companies
- **Deals:** possible sales, each linked to a company, with a value and a stage

Two kinds of users:

- **Sales reps** can view everything and create or edit deals
- **Sales managers** can do all of that, and also mark deals as won

```text
Company 1 ──── many Contacts
Company 1 ──── many Deals
```

## Part 1: Create the project (5 minutes)

<Steps>

1. Create a full-stack project with PostgreSQL and email sign-in:

   ```bash
   pnpm create strutvane@latest acme-crm -- --preset full --db postgres --auth email --yes
   ```

2. Start everything:

   ```bash
   cd acme-crm
   pnpm sv up
   pnpm dev
   ```

3. Open `http://localhost:3000` and sign in with the admin email and password printed in step 1.

</Steps>

**Result:** an empty app with a login page, a dashboard, and **Users** and **Roles** admin screens.

## Part 2: The Company model (10 minutes)

<Steps>

1. Create the model:

   ```bash
   pnpm sv make:model Company name:string:unique website:url:optional "industry:enum(software,retail,finance,other)" --all
   ```

   `--all` also creates a factory (fake data), a seeder and a test.

2. Open the file it created and tweak it. Here we make the name searchable and the industry filterable:

   ```ts title="app/models/company.model.ts"
   import { defineModel, field } from '@strutvane/framework'

   export default defineModel('Company', {
     name:     field.string().unique().searchable(),
     website:  field.url().optional(),
     industry: field.enum(['software', 'retail', 'finance', 'other']).filterable(),
     contacts: field.hasMany('Contact'),
     deals:    field.hasMany('Deal'),
   }, { timestamps: true, softDeletes: true, title: 'name' })
   ```

3. Don't migrate yet, because `Contact` and `Deal` don't exist. We'll migrate once they do.

</Steps>

## Part 3: Contacts and Deals (15 minutes)

```bash
pnpm sv make:model Contact firstName:string lastName:string email:email:unique "company:belongsTo(Company)" --all
pnpm sv make:model Deal title:string "company:belongsTo(Company)" amount:decimal(12,2) "stage:enum(lead,proposal,won,lost)" closeDate:date:optional --all
```

Make the deal stage filterable, and sort deals by amount:

```ts title="app/models/deal.model.ts"
export default defineModel('Deal', {
  title:     field.string().searchable(),
  company:   field.belongsTo('Company').required().filterable(),
  amount:    field.decimal(12, 2).min(0).sortable(),
  stage:     field.enum(['lead', 'proposal', 'won', 'lost']).default('lead').filterable(),
  closeDate: field.date().optional().sortable(),
}, { timestamps: true, audit: true, title: 'title' })
```

`audit: true` records **who changed what, and when**, for every deal.

Now create the tables and add fake data:

```bash
pnpm sv migrate
pnpm sv db:seed
```

**Result:** refresh the browser and you'll see **Companies**, **Contacts** and **Deals** in the menu. Each has a searchable, filterable table, create and edit forms, and detail pages. A company's page shows tabs listing its contacts and deals. A deal's page has an **Activity** tab with its change history.

## Part 4: Roles and permissions (15 minutes)

Strutvane created permissions for every model, such as `deal.view`, `deal.create`, `deal.update` and `deal.delete`. Now decide who gets what:

```bash
pnpm sv auth:role:create sales-rep
pnpm sv auth:role:create sales-manager --inherits sales-rep
```

Then give the roles their permissions in the config file:

```ts title="config/auth.ts"
roles: {
  'sales-rep': [
    'company.viewAny', 'company.view',
    'contact.viewAny', 'contact.view', 'contact.create', 'contact.update',
    'deal.viewAny', 'deal.view', 'deal.create', 'deal.update',
  ],
  'sales-manager': ['deal.delete', 'deal.markWon'], // plus everything from sales-rep
},
```

Check the result as a table:

```bash
pnpm sv auth:matrix
```

```text
permission        sales-rep   sales-manager
deal.view            ✔             ✔
deal.update          ✔             ✔
deal.delete          ✘             ✔
deal.markWon         ✘             ✔
```

**Result:** sign in as a sales rep and the **Delete** buttons are gone. The API refuses deletes too, so even a clever user calling the API directly can't delete deals.

## Part 5: A custom action, "Mark as won" (20 minutes)

This is your business logic. Strutvane gives you a place to put it:

```bash
pnpm sv make:resource Deal
```

```ts title="app/resources/deal.resource.ts"
import { defineResource } from '@strutvane/framework'
import Deal from '../models/deal.model'

export default defineResource(Deal, {
  actions: {
    markWon: {
      permission: 'deal.markWon',
      handler: async ({ record }) => {
        return record.update({ stage: 'won', closeDate: new Date() })
      },
      ui: {
        label: 'Mark as won',
        variant: 'primary',
        confirm: true,
        visibleWhen: (deal) => deal.stage !== 'won',
      },
    },
  },
})
```

**Result:**

- A new endpoint: `POST /api/v1/deals/:id/mark-won`
- A **Mark as won** button on each deal's page, visible only to managers and only while the deal isn't already won
- The change is recorded in the deal's activity history

## Part 6: Polish (20 minutes)

Give the deals table a sensible default view:

```ts title="app/resources/deal.resource.ts" ins={2-5}
export default defineResource(Deal, {
  api: { defaultSort: '-amount' },
  ui:  { icon: 'handshake', group: 'Sales',
         list: { columns: ['title', 'company', 'amount', 'stage', 'closeDate'] } },
  actions: { /* markWon from Part 5 */ },
})
```

## Part 7: Test and build (10 minutes)

```bash
pnpm test     # runs the generated tests, including permission and validation checks
pnpm build    # creates a production build
```

## What you built

- 3 models with relationships
- A full API with search, filters, sorting and pagination, documented at `/docs`
- Sign-in, two roles, and permission checks on every screen and API call
- A custom business action, with change history
- Tests

…in about 2 hours, with every line in your own project, ready to change.
