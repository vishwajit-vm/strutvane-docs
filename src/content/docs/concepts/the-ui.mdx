## Where the screens come from

Your API publishes a **manifest** at `/.well-known/strutvane.json`: a description of every resource, its fields, and what **this** user may do. The UI reads it and draws the screens. You don't write a screen per model.

## What you get for each model

For a model called `Invoice`:

| Screen | Component | What's on it |
|---|---|---|
| List | `<ResourceList>` | A table with search, filter chips, sortable columns and Previous/Next pages. The list state lives in the URL, so you can bookmark or share a filtered list. |
| Create | `<ResourceForm>` | A form with the right input for each field, and validation as you type |
| Edit | `<ResourceForm recordId={id}>` | The same form, pre-filled. Only the fields you changed are sent. |

You decide the addresses (`/invoices`, `/invoices/new`…) with your own router.

Detail pages with related records and an **Activity** tab, a menu, breadcrumbs, global search, bulk actions, export, saved views and dark mode come in later releases.

## The right input for each field type

You never pick inputs by hand. The field type decides:

| Field type | You get |
|---|---|
| `string`, `email`, `url` | A text box (with format checks) |
| `text` | A larger text area |
| `integer`, `decimal` | A number input that keeps exactly what you typed (`1250.` isn't swallowed) and accepts your locale's decimal comma |
| `boolean` | A checkbox |
| `enum` | A dropdown |
| `date` | A date input that only accepts real calendar dates |
| `belongsTo('Company')` | A picker that searches companies on the server, 100 at a time |
| `readOnly` fields | A read-only display |

## It follows your permissions

If a user may not delete invoices, there's no **Delete** button. If a field is hidden from their role, it's not in the table or the form. The API enforces the same rules, so hiding a button is never the only lock.

## When something goes wrong

- A validation problem from the server appears **next to the field** it belongs to, even deep inside a list (`lines[1].amount`). If no field matches, it appears in a banner at the top. No message is ever dropped.
- Other errors (no permission, a conflict, offline, a server error) show a friendly message. What you typed is always kept.
- Pressing **Save** twice never creates two records: each save carries an idempotency key.

## Making it yours

### Change one small thing

Show amounts as money with a currency symbol, and leave everything else automatic. Pass your own **cell** (how a value looks in the list) or **widget** (the input in a form) to the provider:

```tsx title="web/app.tsx"
import type { Cell } from '@strutvane/ui/react'

const Money: Cell = ({ value, record }) => <>{formatMoney(value, record.currency)}</>

<StrutvaneProvider
  api={api}
  manifest={manifest}
  overrides={{
    fieldCells: { 'Invoice.amount': Money },
    messages: { required: '{attribute} is mandatory.' },
  }}
/>
```

Your widgets get labels, help text and error wiring for free, so they're accessible too.
