## What's an API?

An **API** is a doorway that lets other programs, such as your website, a mobile app or a partner's system, read and save your app's data over the internet. Each doorway has an address (an **endpoint**) and an action, such as "get" or "create".

## The endpoints every model gets

For a model called `Invoice`, Strutvane creates:

| Action | Request | What it does |
|---|---|---|
| List | `GET /api/v1/invoices` | Many invoices, with search, filters, sorting and pages |
| Show | `GET /api/v1/invoices/:id` | One invoice |
| Create | `POST /api/v1/invoices` | Make a new invoice (checked against your model) |
| Update | `PATCH /api/v1/invoices/:id` | Change some fields |
| Delete | `DELETE /api/v1/invoices/:id` | Delete (or move to the bin, if soft deletes are on) |
| Restore | `POST /api/v1/invoices/:id/restore` | Bring a soft-deleted invoice back |
| Query | `POST /api/v1/invoices/query` | The same as List, with the filters in the request body (handy for long filters) |

Every request is **validated** (does the data fit the model?) and **authorized** (is this person allowed?). Each app also gets `/openapi.json`, the manifest at `/.well-known/strutvane.json`, and the health checks `/health` and `/ready`.

<Aside type="note" title="Planned">
Export to CSV or Excel, bulk changes and `PUT` (replace a whole record) come in a later release.
</Aside>

## Searching, filtering, sorting and paging

Here are real examples you'll be able to paste into your browser or an API tool.

| I want… | URL |
|---|---|
| Invoices matching "acme" | `/api/v1/invoices?search=acme` |
| Only paid invoices | `/api/v1/invoices?filter[status][eq]=paid` |
| Draft **or** sent | `/api/v1/invoices?filter[status][in]=draft&filter[status][in]=sent` |
| Amount at least 100 | `/api/v1/invoices?filter[amount][gte]=100` |
| Biggest first | `/api/v1/invoices?sort=-amount` |
| Biggest first, then by number | `/api/v1/invoices?sort=-amount,number` |
| 25 per page | `/api/v1/invoices?page[size]=25` |
| 25 per page, with the total count | `/api/v1/invoices?page[size]=25&page[total]=true` |
| Include the customer's details | `/api/v1/invoices?include=customer` |

**Filter operators**, in plain words:

| Operator | Means | Example |
|---|---|---|
| `eq` / `ne` | equals / not equal | `filter[status][eq]=paid` |
| `gt` / `gte` | greater than / at least | `filter[amount][gte]=100` |
| `lt` / `lte` | less than / at most | `filter[amount][lt]=50` |
| `in` / `nin` | one of / none of (repeat the key for each value) | `filter[status][in]=draft&filter[status][in]=sent` |
| `contains` | text contains | `filter[number][contains]=2026` |
| `startsWith` / `endsWith` | text starts / ends with | `filter[number][startsWith]=INV-` |
| `between` | within a range (repeat the key for both ends) | `filter[dueDate][between]=2026-01-01&filter[dueDate][between]=2026-03-31` |
| `isNull` / `isNotNull` | is empty / has a value | `filter[notes][isNull]=true` |

Values are **repeated**, never split on commas, so a value like `"Smith, Jones & Co"` is never cut in half. Text matching ignores upper and lower case for the letters A to Z.

<Aside type="note">
You can only filter, sort or search on fields you marked `.filterable()`, `.sortable()` or `.searchable()` in your model. Anything else, including a typo in a parameter name, is a `422` error that lists **every** problem at once. Filters through relations (`customer.name`) and choosing fields (`fields[invoices]=…`) are **Planned**.
</Aside>

## What a response looks like

<Tabs>
  <TabItem label="List">

```json
{
  "data": [
    { "id": "01J9Z4…", "number": "INV-0042", "amount": "1200.00", "status": "sent" },
    { "id": "01J9Z5…", "number": "INV-0043", "amount": "350.00",  "status": "draft" }
  ],
  "meta": { "page": { "size": 25, "hasMore": true, "nextCursor": "eyJpZCI6…" } }
}
```

To get the next page, add `page[cursor]=` with the `nextCursor` value: `/api/v1/invoices?page[size]=25&page[cursor]=eyJpZCI6…`.

  </TabItem>
  <TabItem label="Create">

```http
POST /api/v1/invoices
Content-Type: application/json

{ "number": "INV-0044", "amount": "99.90", "customer": "01J9Z1…" }
```

```json
{ "data": { "id": "01J9Z6…", "number": "INV-0044", "amount": "99.90", "status": "draft" } }
```

`status` was filled in from the model's default (`draft`).

  </TabItem>
  <TabItem label="Error">

```json
{
  "type": "https://strutvane.dev/errors/validation-failed",
  "title": "Validation failed",
  "status": 422,
  "code": "VALIDATION_FAILED",
  "issues": [
    { "path": ["amount"], "code": "too_small", "params": { "min": 0 }, "message": "Amount must be at least 0." }
  ],
  "fieldErrors": { "amount": ["Amount must be at least 0."] },
  "traceId": "4bf92f3577b34da6"
}
```

Every error has the same shape, following a standard called RFC 9457 ("problem details"). Each entry in `issues` says **where** the problem is (`path`), a stable `code` your code can check, and a friendly `message` from the message catalog. `fieldErrors` is the same information grouped by field, ready for a form. `traceId` helps you find the request in your [logs](../../packages/logs/).

  </TabItem>
</Tabs>

## API docs, for free

Your running app publishes an **OpenAPI** description of every endpoint at `/openapi.json`. It's generated from your models, so it's never out of date, and tools like Postman or API client generators can read it.

<Aside type="note" title="Planned">
An interactive page at `/docs`, with **"Try it"** buttons, comes in a later release.
</Aside>

## Your own endpoints

Need something that isn't create/read/update/delete, like a "revenue report"? Add a **custom route**. It gets the same permission checks and error format:

```ts title="app/http/routes/api.ts"
import { route } from '@strutvane/framework/http'

export default [
  route.get('/reports/revenue', { permission: 'report.revenue', handler: ({ query }) => revenue(query) }),
]
```

Custom actions on a resource, like "approve invoice", are **Planned**. See [Levels of control](../levels-of-control/).
